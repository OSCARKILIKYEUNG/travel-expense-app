# 旅遊手帳 App PRD · 2026-04

> **定位**：把你目前的旅遊記帳工具，擴展成一個覆蓋 **旅前規劃、旅中記錄、旅後回憶** 的 **travel notebook** 產品。  
> **用途**：本檔是未來幾個 phase 的產品需求單一真相來源，回答「要做成什麼、先做什麼、為什麼這樣排」。  
> **不取代**：實作細節與踩坑仍看 `PRODUCT_ITERATION_2025-03.md`；設計敘事看 `DESIGN_THINKING.md`；目前滾動路線與技術債看 `PRODUCT_MANAGEMENT.md`。

---

## 一、產品願景

打造一個像 **旅遊筆記本** 的 App，不只是記帳，而是陪使用者完成整段旅程：

- **旅前**：規劃行程、記錄想去的地方與想買的東西、整理每天安排
- **旅中**：記帳、掃描收據、多人分帳、查看旅途中花費與節奏
- **旅後**：把照片、消費、地點與故事整理成一本可回看的電子旅遊手帳

一句話版本：

> **不是「旅行時順手記帳的工具」，而是「一趟旅程從出發前到回來後的數位旅遊筆記」。**

---

## 二、產品定位

### 2.1 核心定位

本產品應被理解為：

- 一個有審美、有情緒、有回憶感的 **travel notebook**
- 而不是冷冰冰的 expense tracker

### 2.2 差異化

相較一般旅遊 app 或記帳 app，差異在於：

1. **前中後包圍同一段旅程**
   - 不是分散在 itinerary app、expense app、photo album app 三個地方

2. **記帳不是孤立功能**
   - 消費、想買清單、地點、照片、故事都屬於同一趟 trip

3. **產品氣質要像一本手帳**
   - UI 要有 journal / scrapbook / editorial 感，而不是 SaaS dashboard 感

---

## 三、目標使用者

### 3.1 主要使用者

- 會自己規劃旅程的自由行旅客
- 願意記錄旅行細節的人
- 會在旅途中購物、保存收據、回來後回顧照片與故事的人

### 3.2 次要使用者

- 和朋友 / 伴侶 / 家人一起旅行，需要多人分帳的人
- 喜歡收納 wishlist、景點、消費、照片的人

### 3.3 使用者動機

- 出發前不想把靈感散落在備忘錄、地圖、聊天紀錄
- 旅途中想快速記下花費與行程，不想切好幾個 app
- 回來後希望保留旅程脈絡，而不是只剩一堆照片和帳單

---

## 四、Jobs To Be Done

### 4.1 旅前

- 幫我整理想去的地方、想吃的店、想買的東西
- 幫我把零散靈感組成可執行的旅程
- 幫我看到某天要去哪裡、順不順路、還缺什麼安排

### 4.2 旅中

- 幫我快速記錄花費，最好拍照就能進來
- 幫我知道我今天 / 這趟已花多少
- 幫我處理多人代墊與最終誰該還誰

### 4.3 旅後

- 幫我把這趟旅行整理成一本可以回看的記錄
- 不只是相簿，而是帶有「時間、地點、花費、故事」的旅遊手帳

---

## 五、三段式產品結構

### 5.1 前：Trip Planning

定位為 **旅前規劃層**。

預期能力：

- AI 提議行程雛形
- itinerary cards
- 月曆 / 日程視圖
- 想買清單（wishlist / buy list）
- 地圖 pin
- 路線與交通建議

產品原則：

- 規劃層應服務「這一趟 trip」，而不是變成另一個獨立 app
- 初期先做 **輕量規劃**，不要一開始就做很重的 route planner

### 5.2 中：Trip Ledger

定位為 **旅中核心層**，也是目前最成熟、最接近 MVP 的部分。

現有基礎：

- 手動記帳
- AI 掃描收據
- 多旅程
- 幣別與匯率
- Stripe 訂閱與 webhook

未來強化方向：

- 免費額度與 Pro gating
- 多人分帳
- 代墊結算
- A 應還 B 多少、B 應還 C 多少、最終淨額如何結算

### 5.3 後：Trip Memory Book

定位為 **旅後回憶層**。

預期能力：

- 電子旅遊繪本
- 照片 + 地點 + 花費 + 故事的編排頁
- scrapbook / collage / zine 感的旅程回顧
- 可輸出或分享的 recap

產品原則：

- 初期不做完全自由畫布
- 先做 **模板式頁面**，降低製作成本與使用門檻

## 六、設計方向

### 6.1 視覺語言

參考方向：**Paper by WeTransfer**

不是單純擬物，而是借鏡這些特質：

- journal metaphor
- scrapbook 感
- 手感與留白
- editorial / notebook / collage 氣質
- 不要有強烈 SaaS 儀表板味

### 6.2 設計原則

1. **像旅遊手帳，不像公司後台**
2. **像在整理旅程，不像在填表**
3. **情緒價值與實用性並重**
4. **視覺改版先於功能擴張**

### 6.3 第一階段的設計策略

先把以下頁面做成 coherent story：

- Dashboard
- Add Expense
- Settings

Charts、Auth 與更大範圍視覺細節可第二批再精修。

---

## 七、商業模式

### 7.1 現階段建議

- **手動記帳永遠免費**
- **每帳戶終生 5 次免費 AI 掃描**
- 超過後升級 **Pro**
- Pro 解鎖持續掃描

### 7.2 為什麼這樣合理

- 手動輸入幾乎沒有模型成本
- AI 掃描才有明確邊際成本
- 免費 5 次足夠讓新使用者體驗價值
- 規則簡單、好理解、好轉換

### 7.3 第一階段商業目標

不是最大化收入，而是驗證：

- 使用者是否願意為 AI 掃描付費
- 免費額度是否足夠驅動升級
- 旅遊手帳定位是否比單純記帳更有吸引力

## 八、Phase 規劃

## Phase 1：先上架、先收費、先驗證

### 目標

把現有產品變成：

- 有品牌感的旅遊手帳 UI
- 可收費的 AI 掃描產品
- 有免費額度與升級理由的 MVP

### 包含

- UI 大翻新（travel notebook 方向）
- Stripe / webhook 完整收費鏈
- AI 掃描免費額度
- Settings 顯示 Free / Pro / 剩餘次數
- 上架前營運與信任文案

### 不包含

- AI 行程規劃
- 月曆 itinerary
- 地圖 pin
- 路線與交通建議
- 旅後手帳成冊
- 複雜多人代墊結算 UX

### 成功標準

- 新用戶一進來能感知品牌與產品定位
- 可正常手動記帳與 AI 掃描
- 第 6 次掃描時能被清楚擋下
- 訂閱成功後掃描立即恢復
- 可用於第一輪市場驗證與收費測試

## Phase 2：Trip Planning Lite

### 目標

把「旅前」接到現有 trip 容器中。

### 優先功能

- itinerary cards
- day-based notes
- wishlist / buy list
- place pins（可先接 map links）

### 原則

- 先做輕量版
- 不要一開始就做完整 AI route planner

## Phase 3：Trip Memory Book

### 目標

讓旅程不只被記錄，還能被回看與整理。

### 優先功能

- photo + note collage
- trip recap
- 模板式旅遊手帳頁
- exportable travel zine / recap

### 原則

- 先模板、後自由排版

---

## 九、關鍵產品決策

1. **Phase 1 不做大而全**
   - 先把記帳 + 掃描 + 收費 + UI 做對

2. **先做氣質，再做功能擴張**
   - 否則產品會像三個不同方向的工具拼在一起

3. **Trip 是共同容器**
   - 旅前規劃、旅中記錄、旅後回顧，都應屬於同一個 trip

4. **AI 是加速器，不是唯一入口**
   - 規劃可有 AI 建議
   - 記帳可有 AI 掃描
   - 但手動能力要一直存在

## 十、風險與提醒

### 10.1 功能膨脹風險

若旅前、旅中、旅後功能同時展開，會很容易失焦。  
因此必須堅守：

- 先 Phase 1
- 先商業閉環
- 先核心體驗

### 10.2 資料模型風險

旅前規劃與旅後回顧都會引入新資料結構，不能直接硬塞進目前 expense-only 的心智模型裡。  
Phase 2 前應重新設計 `trip` 之下的資訊結構。

### 10.3 視覺與技術脫節風險

如果只換配色，不重做資訊架構與頁面語言，產品依然會看起來像工具型管理系統。  
因此 UI 改版不只是 style pass，而是產品語言重定義。
